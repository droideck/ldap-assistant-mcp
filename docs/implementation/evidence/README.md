# Completion evidence records

Store one sanitized structured record per task at `<TASK_ID>.json`, based on `../templates/EVIDENCE_TEMPLATE.json`. A completed record is valid only when every manifest acceptance criterion and required gate is explicitly `passed`; command/test outcomes agree with integer exit codes; every criterion and non-review gate has passed executable proof; acceptance/G1 evidence covers exactly every manifest `fail_before_cases` ID; its admission-contract, admitted-HEAD, and baseline identities equal the external receipts and local pins; and its reviewed identity equals the SHA-256 of the verified review bundle/completion tombstone. Protected and ignored paths are recorded as unverified, never as content-preservation attestations.

Create `<TASK_ID>-baseline.json` before product edits, surface and pin its SHA-256 before editing, and create `<TASK_ID>-review-bundle.json` after the complete product/test change set and acceptance evidence are frozen. These are generated by the execution Skill's `review_bundle.py`; do not hand-edit them.

Never store credentials, bind DNs, customer identifiers, raw customer logs, ignored configuration, or secrets here. These records prove consistency; the outer tool transcript is the witness that commands actually ran.
